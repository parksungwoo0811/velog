<h3 id="결측치는-없애야-하는-값이-아니라-이유를-확인할-값입니다">결측치는 &quot;없애야 하는 값&quot;이 아니라 &quot;이유를 확인할 값&quot;입니다</h3>
<p>결측치(<code>NaN</code>)는 비어 있는 값입니다. 단순히 0으로 바꾸기 전에 <strong>왜 비었는지</strong>를 생각해야 합니다.</p>
<ul>
<li><strong>MCAR</strong>: 완전히 우연히 비었습니다. 예를 들어 전송 중 일부 행이 누락된 경우입니다.</li>
<li><strong>MAR</strong>: 다른 열과 관련되어 비었습니다. 예를 들어 특정 지역에서만 설문 응답이 적은 경우입니다.</li>
<li><strong>MNAR</strong>: 값 자체의 특성 때문에 비었습니다. 예를 들어 소득이 높은 사람이 소득 응답을 피하는 경우입니다.</li>
</ul>
<pre><code class="language-python"># 열별 결측치 수와 비율

<h3 id="이상치는-오류일-수도-중요한-신호일-수도-있습니다">이상치는 오류일 수도, 중요한 신호일 수도 있습니다</h3>
<p>이상치는 보통 나머지 값과 지나치게 멀리 떨어진 값입니다. 그렇다고 무조건 삭제하면 안 됩니다. <code>999999</code>처럼 입력 오류일 수 있지만, 실제 대형 거래일 수도 있기 때문입니다.</p>
<p>IQR(사분위 범위) 방식은 이상치를 찾는 대표적인 규칙입니다.</p>
<pre><code class="language-text">IQR = Q3 - Q1
하한 = Q1 - 1.5 × IQR
상한 = Q3 + 1.5 × IQR</code></pre>
<pre><code class="language-python">q1 = df[&quot;amount&quot;].quantile(0.25)
q3 = df[&quot;amount&quot;].quantile(0.75)
iqr = q3 - q1
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr

outliers = df.loc[~df[&quot;amount&quot;].between(lower, upper)]
clean_df = df.loc[df[&quot;amount&quot;].between(lower, upper)].copy()

print(f&quot;이상치 후보: {len(outliers)}건&quot;)</code></pre>
<p>여기서 <code>outliers</code>를 먼저 출력해 실제 오류인지 확인하세요. 제거를 결정했다면 왜 제거했는지, 몇 건을 제거했는지 기록해야 분석을 재현할 수 있습니다.</p>
<h3 id="groupby-pivot_table-merge-질문을-표로-바꾸는-세-도구"><code>groupby</code>, <code>pivot_table</code>, <code>merge</code>: 질문을 표로 바꾸는 세 도구</h3>

<h3 id="polars의-핵심-eager와-lazy">Polars의 핵심: Eager와 Lazy</h3>
<p><strong>Eager(즉시 실행)</strong> 모드는 코드를 실행하는 즉시 결과를 만듭니다. 빠르게 확인하기 좋습니다.</p>
<pre><code class="language-python">import polars as pl

sales = pl.read_csv(&quot;sales.csv&quot;)
result = sales.filter(pl.col(&quot;amount&quot;) &gt; 0)</code></pre>
<p><strong>Lazy(지연 실행)</strong> 모드는 바로 계산하지 않고, 먼저 &quot;무엇을 할지&quot; 계획을 모읍니다. 마지막의 <code>collect()</code>에서 실제 계산합니다.</p>
<pre><code class="language-python">result = (
    pl.scan_csv(&quot;sales.csv&quot;)
    .filter(pl.col(&quot;region&quot;) == &quot;서울&quot;)
    .filter(pl.col(&quot;amount&quot;) &gt; 0)
    .group_by(&quot;category&quot;)
    .agg(
        pl.col(&quot;amount&quot;).sum().alias(&quot;total_sales&quot;),
        pl.len().alias(&quot;transaction_count&quot;),
    )
    .sort(&quot;total_sales&quot;, descending=True)
    .collect()
)</code></pre>
<p>여기서 Polars는 가능한 한 빨리 불필요한 행과 열을 제외합니다.</p>
<ul>
<li><strong>Predicate pushdown</strong>: <code>filter</code> 조건을 파일을 읽는 단계 가까이로 밀어 넣어 불필요한 행을 덜 읽습니다.</li>
<li><strong>Projection pushdown</strong>: 실제로 쓰는 열만 읽어 메모리와 시간을 아낍니다.</li>
</ul>
<p>따라서 큰 파일에서는 <code>read_csv()</code>보다 <code>scan_csv() → 변환 체인 → collect()</code> 구조가 핵심입니다. <code>collect()</code>를 빼먹으면 결과 DataFrame이 아니라 아직 실행 전 계획(LazyFrame)만 남습니다.</p>
<h3 id="duckdb-sql을-아는-사람에게-가장-빠른-진입로">DuckDB: SQL을 아는 사람에게 가장 빠른 진입로</h3>
<p>DuckDB는 별도 서버를 띄우지 않고도 CSV나 Parquet 파일을 SQL로 질의할 수 있는 분석용 데이터베이스입니다.</p>
<pre><code class="language-python">import duckdb

region_summary = duckdb.sql(&quot;&quot;&quot;
    SELECT
        region,
        SUM(amount) AS total_sales,
        AVG(amount) AS average_sales,
        COUNT(*) AS transaction_count
    FROM 'data/*.csv'
    WHERE amount &gt; 0
    GROUP BY region
    ORDER BY total_sales DESC
&quot;&quot;&quot;).df()</code></pre>
<p><code>data/*.csv</code>처럼 여러 파일을 한 번에 읽을 수도 있고, <code>JOIN</code>, <code>GROUP BY</code>, 윈도 함수도 사용할 수 있습니다. 분석 결과를 Pandas DataFrame으로 받고 싶으면 <code>.df()</code>, Polars DataFrame으로 받고 싶으면 <code>.pl()</code>을 사용합니다.</p>
<h3 id="csv보다-parquet이-자주-유리한-이유">CSV보다 Parquet이 자주 유리한 이유</h3>
<p>CSV는 사람이 열어 보기 쉬운 텍스트 파일입니다. 반면 Parquet은 <strong>열 단위로 저장하는 바이너리 형식</strong>입니다.</p>
<ul>
<li>필요한 열만 읽기 쉬워 대용량 분석에 유리합니다.</li>
<li>타입 정보가 보존되어 날짜·숫자 처리 오류가 줄어듭니다.</li>
<li>반복 분석용 저장소로 효율적입니다.</li>
</ul>
<p>실무에서는 <code>원본 CSV 수집 → 정제 후 Parquet 저장 → Polars/DuckDB 분석 → Pandas로 결과 확인</code>처럼 도구를 함께 쓰기도 합니다.</p>
<p><strong>여기까지 확인하기</strong></p>
<ul>
<li><input disabled="" type="checkbox" /> 빠른 탐색에는 Pandas, 대용량 변환에는 Polars, SQL 질의에는 DuckDB를 고려한다.</li>
<li><input disabled="" type="checkbox" /> Polars Lazy 작업은 <code>scan_*()</code>으로 시작해 마지막에 <code>collect()</code>한다.</li>
<li><input disabled="" type="checkbox" /> CSV와 Parquet의 목적 차이를 설명할 수 있다.</li>
</ul>

<h3 id="상관관계는-관계의-단서이지-원인-증명은-아닙니다">상관관계는 관계의 단서이지, 원인 증명은 아닙니다</h3>
<p>상관계수는 -1부터 +1 사이의 값입니다.</p>
<ul>

<li><code>-1</code>에 가까움: 한쪽이 증가할수록 다른 쪽은 감소하는 선형 관계가 강함</li>
<li><code>0</code>에 가까움: 선형 관계가 약함</li>
</ul>
<pre><code class="language-python">corr = df[[&quot;amount&quot;, &quot;visits&quot;, &quot;discount_rate&quot;]].corr()
print(corr)</code></pre>
<p>&quot;할인율과 주문 금액의 상관이 음수&quot;라는 결과는 두 값이 같이 움직인다는 뜻일 뿐, 할인율이 주문 금액을 줄였다는 인과관계 증명은 아닙니다. 계절, 고객군, 상품 가격처럼 숨어 있는 요인을 함께 살펴야 합니다.</p>
<h3 id="t-test-두-그룹의-평균-차이가-우연일-가능성을-확인하기">t-test: 두 그룹의 평균 차이가 우연일 가능성을 확인하기</h3>
<p>t-test는 &quot;서울과 부산의 평균 주문 금액이 다른가?&quot; 같은 질문에 사용합니다.</p>
<pre><code class="language-python">from scipy import stats

seoul = df.loc[df[&quot;region&quot;] == &quot;서울&quot;, &quot;amount&quot;]
busan = df.loc[df[&quot;region&quot;] == &quot;부산&quot;, &quot;amount&quot;]
t_stat, p_value = stats.ttest_ind(seoul, busan, equal_var=False)

print(f&quot;t={t_stat:.3f}, p={p_value:.4f}&quot;)
if p_value &lt; 0.05:
    print(&quot;유의수준 0.05에서 두 지역의 평균 차이는 통계적으로 유의합니다.&quot;)
else:
    print(&quot;관측된 차이만으로는 평균이 다르다고 판단하기 어렵습니다.&quot;)</code></pre>
<p><code>p &lt; 0.05</code>는 &quot;두 그룹의 실제 평균이 같다고 가정했을 때, 지금 정도의 차이가 우연히 나올 가능성이 낮다&quot;는 뜻입니다. 이것은 <strong>효과의 크기</strong>나 <strong>비즈니스 중요도</strong>를 뜻하지는 않습니다. 1원 차이도 표본이 매우 크면 유의할 수 있습니다.</p>
<h3 id="카이제곱-검정-두-범주가-독립적인지-확인하기">카이제곱 검정: 두 범주가 독립적인지 확인하기</h3>
<p>예를 들어 지역과 카테고리의 분포가 관련이 있는지 보려면 분할표와 카이제곱 검정을 사용합니다.</p>
<pre><code class="language-python">from scipy.stats import chi2_contingency

table = pd.crosstab(df[&quot;region&quot;], df[&quot;category&quot;])
chi2, p_value, dof, expected = chi2_contingency(table)

print(f&quot;chi2={chi2:.3f}, p={p_value:.4f}&quot;)</code></pre>
<p>여기서도 <code>p &lt; 0.05</code>라면 두 범주는 독립적이라고 보기 어렵다는 뜻입니다. 어느 조합이 특히 많이 또는 적게 나타나는지는 원래 분할표와 기대 빈도를 함께 확인해야 합니다.</p>
<h3 id="머신러닝-파이프라인-학습과-예측에서-같은-전처리를-보장하기">머신러닝 파이프라인: 학습과 예측에서 같은 전처리를 보장하기</h3>
<p>머신러닝 모델은 좋은 알고리즘보다 <strong>일관된 데이터 준비</strong>가 먼저입니다. <code>Pipeline</code>은 전처리와 모델을 한 덩어리로 묶어 학습 때와 예측 때 같은 과정을 적용하게 합니다.</p>
<pre><code class="language-python">from joblib import dump
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import Ridge
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

numeric_features = [&quot;discount_rate&quot;, &quot;visits&quot;]
categorical_features = [&quot;region&quot;, &quot;category&quot;]

preprocessor = ColumnTransformer(
    transformers=[
        (
            &quot;num&quot;,
            Pipeline(
                [
                    (&quot;imputer&quot;, SimpleImputer(strategy=&quot;median&quot;)),
                    (&quot;scaler&quot;, StandardScaler()),
                ]
            ),
            numeric_features,
        ),
        (
            &quot;cat&quot;,
            Pipeline(
                [
                    (&quot;imputer&quot;, SimpleImputer(strategy=&quot;most_frequent&quot;)),
                    (&quot;onehot&quot;, OneHotEncoder(handle_unknown=&quot;ignore&quot;)),
                ]
            ),
            categorical_features,
        ),
    ]
)

model = Pipeline(
    steps=[
        (&quot;preprocess&quot;, preprocessor),
        (&quot;regressor&quot;, Ridge(alpha=1.0)),
    ]
)

# model.fit(X_train, y_train)
# print(model.score(X_test, y_test))
# dump(model, &quot;models/sales_model.joblib&quot;)</code></pre>
<ul>
<li><code>ColumnTransformer</code>: 숫자 열과 범주형 열에 서로 다른 전처리를 적용합니다.</li>
<li><code>Pipeline</code>: 전처리와 모델을 순서대로 연결합니다.</li>
<li><code>fit()</code>: 전처리 기준과 모델의 규칙을 학습합니다.</li>
<li><code>predict()</code>: 학습한 규칙으로 새 값의 결과를 예측합니다.</li>
<li><code>joblib.dump()</code>: 전처리까지 포함한 모델 전체를 저장합니다.</li>
</ul>
<p>이 구조가 중요한 이유는 새 데이터 예측 때도 원-핫 인코딩, 결측치 처리, 스케일링을 <strong>학습 때와 똑같이</strong> 적용하기 때문입니다.</p>
<h2 id="12-분석-자동화와-파이프라인-설계">12. 분석 자동화와 파이프라인 설계</h2>
<h3 id="자동화할-일과-사람이-판단할-일을-구분하기">자동화할 일과 사람이 판단할 일을 구분하기</h3>
<p>매주 같은 파일을 읽고, 같은 집계를 하고, 같은 형식의 보고서를 만드는 일은 자동화 후보입니다. 반면 &quot;이번 달의 급격한 변화는 왜 일어났는가?&quot; 같은 해석과 의사결정은 사람이 해야 할 일입니다.</p>
<p>좋은 분석 파이프라인은 다음 특징을 가집니다.</p>
<pre><code class="language-text">Extract(수집) → Validate(검증) → Transform(정제·변환) → Analyze(분석)
→ Report(공유) → Monitor(오류·품질 확인)</code></pre>
<ul>
<li>각 단계의 함수가 분리되어 있다.</li>
<li>실패한 위치와 원인을 로그로 남긴다.</li>
<li>같은 입력이면 같은 결과가 나와야 한다.</li>
<li>각 단계를 독립적으로 테스트할 수 있다.</li>
</ul>
<pre><code class="language-python">def run_pipeline(config: dict) -&gt; dict:
    raw = extract(config[&quot;source&quot;])
    validated, errors = validate(raw)
    cleaned = transform(validated)
    summary = analyze(cleaned)
    report_path = render_report(summary)
    return {&quot;summary&quot;: summary, &quot;errors&quot;: errors, &quot;report_path&quot;: report_path}</code></pre>
<h3 id="일정-실행-개발용-schedule-운영용-os-스케줄러">일정 실행: 개발용 <code>schedule</code>, 운영용 OS 스케줄러</h3>
<p><code>schedule</code>은 Python 프로그램 안에서 간단히 반복 작업을 예약할 때 좋습니다.</p>
<pre><code class="language-python">import logging
import schedule
import time

def run_daily_report() -&gt; None:
    try:
        # run_pipeline({&quot;source&quot;: &quot;data/sales.csv&quot;})
        logging.info(&quot;일일 리포트 생성 완료&quot;)
    except Exception:
        logging.exception(&quot;일일 리포트 생성 실패&quot;)

schedule.every().day.at(&quot;08:00&quot;).do(run_daily_report)

while True:
    schedule.run_pending()
    time.sleep(60)</code></pre>
<p>이 방식은 프로그램이 계속 실행 중이어야 합니다. 실제 운영에서는 macOS의 <code>launchd</code>, Linux의 <code>cron</code>, 또는 클라우드 스케줄러처럼 운영체제·플랫폼 차원의 스케줄러를 사용하는 경우가 많습니다.</p>
<h3 id="jinja2로-반복-리포트-만들기">Jinja2로 반복 리포트 만들기</h3>
<p>Jinja2는 HTML 템플릿에 분석 결과를 채워 넣는 도구입니다. 파이썬에서 계산한 숫자와 Plotly 차트를 넣으면 매일 같은 구조의 보고서를 자동 생성할 수 있습니다.</p>
<pre><code class="language-python">from pathlib import Path
from jinja2 import Environment, FileSystemLoader

env = Environment(loader=FileSystemLoader(&quot;templates&quot;))
template = env.get_template(&quot;report.html&quot;)

html = template.render(
    title=&quot;일일 판매 리포트&quot;,
    summary={&quot;total_sales&quot;: 1_250_000, &quot;transaction_count&quot;: 840},
)
Path(&quot;output/report.html&quot;).write_text(html, encoding=&quot;utf-8&quot;)</code></pre>
<p>자동화 결과는 성공만 기록하면 부족합니다. 처리 시간, 입력 행 수, 오류 행 수, 생성 파일 경로도 함께 남기면 다음 오류를 훨씬 빠르게 찾을 수 있습니다.</p>

<h2 id="2일차-핵심-요약">2일차 핵심 요약</h2>
<ol>
<li>분석은 <code>info()</code>, <code>describe()</code>, 결측치 확인처럼 데이터 상태를 점검하는 EDA에서 시작합니다.</li>
<li>결측치와 이상치는 기계적으로 삭제하지 말고 원인·영향·처리 기준을 기록합니다.</li>
<li><code>groupby</code>, <code>pivot_table</code>, <code>merge</code>는 비즈니스 질문을 표 형태의 답으로 바꾸는 핵심 도구입니다.</li>
<li>Pandas는 탐색, Polars는 대용량 변환, DuckDB는 SQL 기반 파일 분석에 강점이 있습니다.</li>
<li>좋은 차트는 한 질문에 답하며, 숫자 요약만으로 놓칠 수 있는 패턴을 보여 줍니다.</li>
<li>상관관계와 p-value는 판단의 근거이지, 인과관계나 비즈니스 중요도를 자동으로 증명하지 않습니다.</li>
<li>ML Pipeline은 학습과 예측의 전처리를 동일하게 보장하는 재현성 장치입니다.</li>
<li>자동화·프로젝트 구조화·README는 분석을 한 번의 작업이 아니라 다시 실행 가능한 제품으로 만듭니다.</li>
</ol>
